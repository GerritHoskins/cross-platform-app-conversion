## Android ViewTreeObserver ownership and isAlive

sdk/android/view/View.java:27242-27259 returns the attached hierarchy's observer when mAttachInfo exists; otherwise it creates/returns a floating observer. A detached getter is NOT a lookup of the former attached hierarchy. At attach, View.java:22864-22874 merges the floating observer into the attached tree and clears mFloatingTreeObserver. ViewTreeObserver.java:430-435 transfers pre-draw listeners and :494 kills the old observer. A Page loaded event can precede native attach; therefore the observer saved in F5 need not be the observer that later owns its listener.

ViewTreeObserver.java:1043-1044 isAlive() only reads mAlive on an existing Java object. checkIsAlive():1027-1031 throws the different "This ViewTreeObserver is not alive" error; add/remove check it at :698-705 and :717-722. F6 instead fails before entering isAlive: NativeScript cannot resolve the Java receiver. Optional chaining only checks JS null/undefined and does not make an invalid Java proxy safe. Consequently F5's fallback expression never reaches page.android.getViewTreeObserver().

View.java:22935-22979 calls OnAttachStateChangeListener.onViewDetachedFromWindow(this) at :22967 BEFORE mAttachInfo=null at :22979. This is the last reliable current-view lookup of the still-owned attached tree, even if the old hierarchy remains live for other Pages. Attach merges first (:22872-22874) and dispatches attach listeners later (:22891-22901). These are the cleanup and reattach boundaries used below.

## Chosen smallest complete change

Only Schedule.vue, SessionDetail.vue and TrackFilter.vue change, with identical lifecycle blocks:

- Remove statusBarObserver entirely. Each registration/removal gets a fresh observer from the view supplied NOW. No ViewTreeObserver, Window, controller, or native View is saved across events.
- Keep the exact F5 OnPreDraw body, Page identity/isLoaded guards, API30+ Page-loaded registration, closest-window lookup and conditional updateStatusBarStyle('dark') only when APPEARANCE_LIGHT_STATUS_BARS is clear.
- Keep a plain-JS registration boolean, plus the pre-draw and attach callback identities. Detach removes from the current attached observer before AttachInfo is cleared. Unload removes from the current view and unregisters the attach callback, then clears JS state. Repeated unload is harmless. If detach already removed, unload does not ask a now-detached view for a different floating observer. If attach follows initial floating registration, the merge already transferred it, so the boolean prevents a duplicate; after a genuine detach, reattach while still loaded registers it again.
- The Page object is a NativeScript JS View, not a cached Java native proxy. Native getter reads and all observer/window/controller use remain synchronous. Existing non-status code obtains native objects locally for immediate use; none stores them across lifecycle events.

No try/catch is needed: the inspected unload paths preserve the native View until teardown, and attach/detach callbacks supply a live native View at dispatch. The fresh observer remains owned by that view/tree for the immediate synchronous operation. We avoid the invalid proxy rather than catch it, and do not suppress unrelated native or application errors. There is no timer, process event handler, native monkeypatch, dependency/config/manifest change or state extraction. Merely deleting the cached observer would be smaller but incorrect for a detached Page whose former hierarchy remains alive; the detach callback is the minimum extra lifecycle hook to close that hole. All other F1/F3/F5 templates/styles/logic remain byte-identical; probes check that and check lifecycle permutations without pretending to reproduce ART or Android scheduling.
