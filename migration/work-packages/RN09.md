- **List navigation:** in each speaker card, the name/photo header and the `About <name>` row push `/speakers/speaker/<id>`; each session row pushes `/speakers/session/<sessionId>`. Rows become buttons with accessible names (`<name>`, `About <name>`, `<session name>`). Keep RN08's test IDs.
- **Photos (CD6):** copy the 13 JPEGs from `public/assets/img/speakers/` byte-identically to `migration/react-native/assets/images/speakers/` (same file names). A static map module (for example `src/data/speaker-photos.ts`) maps each source URI (`profilePic`, e.g. `/assets/img/speakers/bear.jpg`) to `require(...)` of the bundled file; an unknown or empty URI maps to no image (CD3 defensive rule). No resizing, recompression or network images.
- **Accessibility:** list photos are decorative (hidden from accessibility; the button already has the name); the detail photo has the label `Profile photo of <name>`. Detail name has role `header`.
- **Speaker detail (CD3):** found → photo, name, title, biography (`about`), no social invitation, no contact/share/social controls. Malformed or unknown ID → an explicit not-found state (`Speaker not found.` plus a short hint), no stale record, header Back still works. While the conference is loading or failed, show the same loading/error-with-Retry pattern as the other screens; resolve with core `findSpeakerByRouteId` only once data is ready. Route params can be `string | string[] | undefined`; pass the raw param value to core (an array is malformed), do not trim or pick the first element.
- **Privacy scan exemption:** the 13 photos are the only binary image files allowed in this packet. The scan must still check them: each must be byte-identical to its `public/` source and match `/speakerDetails` SHA-256 and size; any other image signature or base64 image marker in any file is BLOCKED.
