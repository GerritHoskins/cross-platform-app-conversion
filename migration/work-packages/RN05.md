## State contract addition

In `conference-state.tsx` export:

- `TrackOption`: `{ name: string; checked: boolean }`.
- `selectTrackOptions(state): TrackOption[]` returns `[]` unless status is ready with a conference and selection. Otherwise it returns `sortTracksByName(conference.tracks)` (public core API) mapped to `{ name, checked: selection.selectedTracks.includes(name) }`. Pure; do not store it in state.

Source `isFirstLoad` needs no separate flag: `createInitialSelection` already selects every session track, and the fixture's 10 top-level tracks equal the 10 session tracks, so "all checked on first load" and "mirror the applied filter afterwards" are the same rule here. Record that equivalence and its fixture basis in the handoff; if the sets ever differ, that is a contract question, not a silent choice.

## Filter screen contract

- `FilterScreen()` (default export) reads `useConference()`. Idle/loading: `Loading sessions…` with progress semantics. Error: `Unable to load sessions.`, the message and a labeled `Retry`. Done is disabled until ready.
- The draft is local React state initialized once from `selectTrackOptions(state)` when the conference becomes ready while the screen is mounted. The draft is never written to the reducer until Done. Re-opening the route creates a fresh draft from the currently applied selection.
- Heading `Tracks`; one row per track in `sortTracksByName` order (`Communication, Design, Documentation, Food, Ionic, Navigation, Services, Tooling, Vue, Workshop` for this fixture). Each row is a `Pressable` with `accessibilityRole="checkbox"`, `accessibilityLabel` = track name, `accessibilityState={{ checked }}`, a visible check indicator and the name. Pressing toggles only that row in the draft. No icons: the source shows track icons only on iOS (`SessionListFilter.vue:23`).
- Controls (Android source parity, `SessionListFilter.vue:5-8,13,37-40`): `Reset` clears the draft (all unchecked), `Deselect All` clears the draft, `Select All` checks every draft row, `Done` applies. All are labeled accessible buttons inside the screen, not header slots, keeping the screen independent of navigator internals. Reset is not Cancel: it never closes the modal and never touches applied state.
- Done: dispatch `setSelectedTracks` with the checked names in displayed (sorted) order, then `router.back()`. An empty draft is allowed and applies zero tracks (source parity: zero selected tracks means no sessions).
- Cancel/close: dismissing the modal without Done (the native stack header back/close, `router.back()` in tests, Android Back in RN07) dispatches nothing; the draft is discarded. **Decision:** no separate Cancel button, matching the Android source, which has none (`SessionListFilter.vue:6` is iOS-only). The approved close affordance is the stack header's back/close button. Record this so RN07 E06 can cite it.
- `presentation: 'modal'` on Android may render as a full-screen card without a backdrop or swipe-down; RN07 E08 records unsupported dismiss gestures as N/A. Do not add modal gestures.
