## Approved interfaces this package builds on

- `schedule-screen.tsx` `Row({ session, palette })`: a `View` with `testID="session-<id>"`, a `Pressable` with `accessibilityRole="link"` that calls `router.push({ pathname: '/session/[sessionId]', params: { sessionId: String(session.id) } })`, and a sibling `Pressable` button labeled `Favorite <name>` / `Remove <name>` that calls `handleFavorite`.

## Swipe interaction contract

Grounded in the source unless marked **proposed**:

- **Direction and side.** The source's `<ion-item-options>` has no `side`, so Ionic places options at the end; in left-to-right layout they are revealed by dragging the row from right to left. Implement `renderRightActions` only, with no left actions. [static: `SessionList.vue:82-97`]
- **Action content.** All mode: one action labeled `Favorite`. Favorites mode: one action labeled `Remove`. [static: `SessionList.vue:83-96`]. Pressing the revealed action calls the same `handleFavorite` as the row button, so add-immediately-then-inform, the already-favorite quirk, and remove-with-confirmation are identical. No second implementation of favorite logic.
- **Closing after an action (source parity).** The source closes the sliding item when the alert button is pressed: OK after Favorite Added, Cancel or Remove in the confirmations. [static: `SessionList.vue:312-319,333-347`] Extend `handleFavorite` with an optional `onSettled?: () => void` that is called from every alert button's `onPress` (OK, Cancel, Remove). The row button passes nothing; the swipe action passes `() => methods.close()`. Dispatch order and alert text must not change.
- **Thresholds (proposed; source feel is unverified, `contract.md:52`).** `friction={2}`, `rightThreshold={40}`, `overshootRight={false}`, default `dragOffsetFromRight` (−10, the pan's horizontal activation offset). Action panel width ≈ 96 dp with a `minHeight` of 48 dp. Record any change and the reason.
- **One open row at a time (proposed; Ionic's default list behavior, unverified in the contract).** `ScheduleScreen` keeps a ref to the currently open row's methods. `onSwipeableWillOpen` closes a different previously open row. `onSwipeableClose` clears the ref when it points to that row.
- **Close on list changes (proposed; narrowed by amendment A1).** When search text, mode or selected tracks change, close any open row, so no action panel stays open on a row whose action changed meaning. Favorite changes do **not** trigger this close: they always come from `handleFavorite`, which closes the row through `onSettled` when the alert button is pressed, so the row stays open until OK, Cancel or Remove (source parity, acceptance test 2).
- **No accidental detail navigation.** The row link's `onPress` checks whether that row is open (or opening). If so, it closes the row and does **not** navigate. A completed swipe must not trigger the link. Native verification is required (RN07 F02/F03 precursors).
- **Vertical scrolling.** No `failOffsetY` override is needed: the pan activates only after the horizontal `activeOffsetX`, so mostly vertical drags stay with the `SectionList`. If the device shows vertical drags opening rows, record it and propose a bounded fix; do not silently add gesture relations.
- **State preservation.** Swiping never changes search text, mode, filters or navigation. Favorites change only through the existing handler.
- **Accessibility.** Keep the visible `Favorite <name>` / `Remove <name>` buttons unchanged as the accessible path (RN07 F05). Hide the revealed action panel from assistive technology (`accessibilityElementsHidden` and `importantForAccessibility="no-hide-descendants"`) so each action is announced once, and give the action panel `testID="swipe-action-<id>"` for tests.
- **Keys and recycling.** Keep `keyExtractor` by `String(session.id)`, so a swipeable's state belongs to one session (RN07 F04 precursor).
