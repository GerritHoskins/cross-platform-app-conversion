## Phases and sessions

Each phase is a fresh Hermes session with its own run directory under `tools/qwen-supervisor/.runs/`, a checkpoint `migration/handoffs/RN07-checkpoint-<phase>.md` and `result.json`. Retries never overwrite earlier evidence: they use a new suffixed run-id.

1. **A — candidate and software gates** (checklist A01–A03, A06 software part). No device input.
2. **B — device behavior run** (checklist A05, A06 device windows, groups B–F) at default settings. Hardware Back is **authorized in this phase only for D02, D05, E07 and G01**, and only after XML confirms the intended screen and keyboard state.
3. **G — settings run** (checklist G01–G09) under decision D2, with record → change → test → restore per setting.
4. **Coordinator pixel inspection** of all B and G frames: `migration/evidence/RN07/pixel-inspection-coordinator.md`.
5. **F — fixes (only if a case FAILs).** Each fix creates a new candidate: rerun A gates plus the affected cases and their regression neighbours in a new run-id; never combine old frames with new source hashes.
6. **C — results, handoff and freeze**, then one independent review.

## Device input rules (lessons from RN03–RN06)

- Before every tap or gesture: dump UI XML and confirm the target's bounds; wait 1.5 s; act; wait 2.0 s; dump again. A dump right after an action can still show the previous screen.
- keyevent 4 (Back) only where the phase authorizes it. Never use it to dismiss a keyboard outside G01; record the keyboard state (`dumpsys input_method`) before and after.
- With the keyboard open, the first list tap only dismisses it (known issue). Record it; do not work around it silently.
- Horizontal reveal: `adb shell input swipe <rowRight-40> <rowCenterY> <rowRight-400> <rowCenterY> 300`. Vertical scroll: `adb shell input swipe 540 1800 540 900 400`. Diagonal (F02): record exact coordinates.
- Baseline = a genuinely new process: `am force-stop dev.translationtest.rn`, `am start -n dev.translationtest.rn/.MainActivity`, connect to `http://127.0.0.1:8082` through the development-client launcher UI. Record each relaunch; favorites and filters reset by design.
- Never stop or restart Metro or the emulator, change unlisted settings, install, clear data or reboot.

## Fix policy (target-only, in-scope)

A fix is allowed only for a case that has FAILed, must be the smallest change that makes that case pass, and may touch only:

- `migration/react-native/src/screens/schedule-screen.tsx`, `filter-screen.tsx`, `session-detail-screen.tsx`, `src/app/_layout.tsx`, `src/state/conference-state.tsx`;
- their tests in `migration/react-native/__tests__/` and `test-utils/gesture-test-setup.ts`.

No dependency, lockfile, native, Babel, Metro, Jest, tsconfig or `app.json` change. No debug routes or test-only product controls. Every fix is recorded with the failing case, the diff, a new candidate hash and the rerun evidence.

- **Pre-identified F-1 (expected for G02):** set `keyboardShouldPersistTaps="handled"` on the schedule `SectionList`, so taps on rows, buttons and revealed actions work while the keyboard is open. Add a focused test asserting the prop. Apply only if G02 FAILs as expected.
