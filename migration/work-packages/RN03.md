## State and component contract

Use React `useReducer` plus context; no Vuex, Redux, Zustand, persistence or copied domain algorithms. Define these exports in `conference-state.tsx`:

- `ConferenceState`: `status: 'idle' | 'loading' | 'ready' | 'error'`, `conference: Conference | null`, `selection: Selection | null`, `error: string | null`.
- `createConferenceState(): ConferenceState`: idle, no conference/selection/error; return fresh state each call.
- `ConferenceAction`, a discriminated union: `loadStarted`; `loadSucceeded` with `conference`; `loadFailed` with `error` string; `setSearchText` with `searchText`; `setMode` with `mode: ScheduleMode`; `setSelectedTracks` with readonly `selectedTracks`; `setFavoriteIds` with readonly `favoriteIds`.
- `conferenceReducer(state, action)`: pure/immutable. First successful load initializes selection with public `createInitialSelection(conference)` (all session tracks in first-appearance order, empty search/favorites, all mode). Later loads preserve an existing selection. Loading clears an earlier error but retains previously loaded data/selection; failure sets the error and retains them too. Selection actions before selection exists are no-ops. Copy incoming arrays so later caller mutation cannot change state. Non-related fields survive every selection action.
- `selectScheduleGroups(state): SessionGroup[]`: empty unless status is ready and conference/selection exist; otherwise exactly `groupSessions(selectSessions(conference.sessions, selection))` through the public core API. Do not store derived lists/groups in state.
- `ConferenceProvider({ children, loader? })`: default loader is existing synchronous `loadConference`; optional injected loader has type `() => Conference | Promise<Conference>` for controlled tests. Perform initial load after mount through an asynchronous promise boundary, catching both synchronous throws and rejected promises. Do not call the loader in render. Expose an explicit retry callback. Ignore stale completions from superseded requests and after unmount; development effect replay must not let an older request overwrite a newer result. A request-generation ref with cleanup is sufficient; no cancellation library.
- `useConference()`: returns `{ state, dispatch, retry, groups }`, with groups derived from current state. Throw a descriptive error if used outside the provider.

The selected tracks/favorite IDs actions establish RN04/RN05 integration boundaries; RN03 does not expose editing controls for them. Loading/error/retry behavior is a target concern around a bundled synchronous loader, not a claim that data comes from a network service.

## Schedule UI contract

- Keep a visible accessible `Conference` heading and existing Conference stack title. Use a full-height native layout with readable light/dark colors; no HTML or DOM APIs.
- Render a labeled search TextInput (`Search sessions`) and two accessible mode controls labeled `All sessions` and `Favorite sessions`. Mark the active mode with selected accessibility state. Search dispatches the exact input without trimming/debounce: core preserves whitespace and uses case-insensitive session-name matching. Search stays intact across mode changes.
- Idle/loading: visible `Loading sessions…` with progress semantics. Error: visible `Unable to load sessions.` plus the captured error message and a labeled `Retry` button. Retry starts a new load. Disable search/mode controls until ready; do not display stale rows underneath loading/error UI.
- Ready: use real React Native `SectionList`, not ScrollView plus a mapped list or a FlatList pretending to have sections. Convert each shared `{ groupTime, sessions }` into a section with `data: sessions`. Section headings display groupTime; row keys use `String(session.id)` and sections use groupTime. Preserve shared group/row order; never sort or filter again in the screen.
- Each noninteractive row shows session name, original timeStart–timeEnd strings, location and track names. Provide a stable row testID `session-<id>` for focused virtualization-aware tests. No row navigation, stars, share controls, confirmation dialogs, track selector or gesture handlers yet.
- Empty ready result: `No favorite sessions.` for favorites mode with zero favorite IDs; otherwise `No sessions match your search or filters.` Loading/failure must not masquerade as empty results.
- Switching modes/search is local state only: do not reload the fixture or reset favorites/tracks. Preserve ordinary text sizing and list scrolling. Do not introduce keyboard-dismiss/back behavior outside this package.
