## Decisions to answer (human)

- **D1 — Vuex dependency.** Recommended: add `"vuex": "4.1.0"` (exact) as a runtime dependency and let npm resolve its `vue` peer without a direct `vue` dependency; the bundle uses the template alias (`vue` → `nativescript-vue`), so only one runtime-core ships. Lockfile changes are limited to vuex, the resolved `vue` peer and its `@vue/*` packages; the executor records the delta and stops on any other churn or a peer conflict. No `--legacy-peer-deps`, no `.npmrc`. Alternative: also pin `vue` to the version nativescript-vue's runtime-core resolves, so Vitest and the device run the same reactivity version (more lockfile surface).
- **D2 — store shape.** Recommended: one module `src/state/conference-store.ts` exporting `createConferenceStore(loader?)` (a fresh Vuex store per call; default loader is NS02's `loadConference`), an `InjectionKey` and a typed `useConferenceStore()`. State `{ status: 'idle' | 'loading' | 'ready' | 'error', conference, selection, error }` as in RN03. Mutations mirror RN03's actions (`loadStarted`, `loadSucceeded`, `loadFailed`, `setSearchText`, `setMode`, `setSelectedTracks`, `setFavoriteIds`) with the same rules: the first success initializes selection through public `createInitialSelection`, later loads keep it, loading/failure keep earlier data, selection mutations before load are no-ops, incoming arrays are copied. Getter `scheduleGroups` = `groupSessions(selectSessions(conference.sessions, selection))`, empty unless ready; derived data is never stored. Actions `load` and `retry` call the loader behind a promise boundary, catch sync throws and rejections, and ignore stale completions through a request-generation counter. `strict: false` (immutability is proven by tests instead). Alternative: a namespaced `sessions` module mirroring the source store layout — closer to Ionic, but more surface than the slice needs.
- **D3 — list.** Recommended: NativeScript-Vue `ListView` over flat rows from a pure `toScheduleRows(groups)` in `src/state/schedule-rows.ts`: `{ kind: 'header', key: 'h:<groupTime>', groupTime }` then `{ kind: 'session', key: 's:<id>', session }` per session, in shared group/row order; `itemTemplateSelector` picks the `header` or `session` template. Headers are not sticky. Alternative: the `@nativescript-community/ui-collectionview` plugin (sticky headers, more control), which adds a native dependency and is not recommended for this slice.
- **D4 — tests.** Recommended: Vitest only for store, getter and row logic, using the real public core, real loader and all 11 frozen reference cases (as RN03 tests 1–4, through mutations and `scheduleGroups`); lifecycle cases (pending, throwing and rejecting loaders, retry success, stale completion) through controlled loaders. Test-only import of `../../reference/expected-cases.json` is allowed; never import it in app code. Component rendering and taps are proven on the device, not in Vitest (as NS02 D3); this is weaker UI test coverage than RN03 and is disclosed. Alternative: add a NativeScript unit-test runner (`@nativescript/unit-test-runner`, on-device Jasmine/Karma) — a new toolchain, not recommended here.
- **D5 — device observation.** Recommended: rebuild the debug APK, `adb install -r`, cold launch; capture PNG + compressed UI XML for: initial schedule (title, search field, mode control, first heading `8:00 am`, `Breakfast` row); after `input swipe` scrolls to the last group; after tapping `Favorite sessions` (`No favorite sessions.`); after tapping `All sessions` (rows back). Taps use bounds from the UI XML. No text input: search, no-match and clear are proven by store tests and disclosed as device-unverified. Alternative: lift the no-text-input rule for this package only and type the fixed string `IOnic` with `input text`, with every frame checked for keyboard suggestions and clipboard chips.
- **D6 — controls.** Recommended: native `SearchBar` (hint `Search sessions`; `textChange` commits the exact text, no trim or debounce) and a native `SegmentedBar` with `All sessions` / `Favorite sessions` (the Ionic page uses `ion-segment`). On Android the SearchBar must not take focus or open the keyboard at launch; clear its focus on load and record how. Fixed light palette as NS01/NS02; dark mode is NS07's concern. Alternative: two `Button`s with selected styling and accessibility state instead of the SegmentedBar.

## Schedule UI contract

- ActionBar title `Conference`. Loading (`idle`/`loading`): `Loading sessions…` with an `ActivityIndicator`, no rows. Error: `Unable to load sessions.`, the captured message and a `Retry` button that dispatches `retry`. Controls are disabled until ready; stale rows never show under loading or error.
- Ready: header rows show `groupTime`; session rows show name, original `timeStart`–`timeEnd`, location and track names. Rows are not interactive yet (no tap, star, share or swipe). Each session row carries `automationText` `session-<id>` for UI XML checks.
- Empty ready result: `No favorite sessions.` in favorites mode with no favorite IDs, otherwise `No sessions match your search or filters.` Loading/failure never shows as empty.
- Mode and search changes are store mutations only: no reload, no reset of tracks or favorites; search survives mode switches. The screen never sorts or filters again.
