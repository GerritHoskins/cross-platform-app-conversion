## Outcome and boundaries

Add the session detail page and the favorite controls to the NativeScript target. This is the NativeScript counterpart of RN04, with the same business cases: rows open a detail page inside the root `Frame`; the detail favorite toggle acts immediately with no dialog; the list's Favorite/Remove actions follow the source's immediate-then-confirm semantics through native dialogs (including the reproduced already-favorite quirk); unknown IDs show `Session not found.`; a cold direct entry to a session works through a development-only harness; back from detail returns to the same schedule page with its state. Favorites stay in memory. Filter modal (NS05), swipes (NS06), the speakers entry, sharing and the placeholder actions' behavior are out of scope. No dependency changes.

## Decisions to answer (human)

- **D1 — navigation.** Recommended: rows call `$navigateTo(SessionDetail, { props: { sessionId: String(id) } })` on the root `Frame` from `Home.vue`. `SessionDetail.vue` takes only `sessionId: string`, never imports `Schedule.vue`, reads no back stack and never assumes the schedule is its parent (speakers entry stays reusable). Back uses the ActionBar's system navigation button (Android shows it when the frame can go back); the schedule page stays mounted in the back stack, so search, mode, favorites and scroll position survive and the loader is not called again. Alternative: a router plugin (e.g. a community navigator) — a new dependency, not recommended.
- **D2 — store additions.** Recommended: in `conference-store.ts` add mutations `favoriteAdded(sessionId)` / `favoriteRemoved(sessionId)` that apply public core `addFavorite` / `removeFavorite` to the current `selection.favoriteIds` inside the mutation (consecutive commits compose; duplicate add and absent remove leave IDs equal; no-ops before a selection exists; other fields survive; `replaceState` as NS03), and method-style getters `sessionById(id: number): Session | undefined` (undefined unless ready) and `isFavorite(id: number): boolean` (false without a selection). Extend the `ConferenceStore` getters type. Keep every NS03 export and behavior; `setFavoriteIds` stays for tests. Alternative: compute the new favorite list in components — rejected by RN04 (stale captured values).
- **D3 — ID resolution.** Recommended: same rule as RN04 — a session ID is valid only when the raw string is ASCII decimal digits and its numeric value matches a loaded session; `abc`, `3abc`, `-1`, empty and unmatched numbers are unknown. Pure `parseSessionId(raw): number | undefined` in NEW `src/state/session-detail.ts`. Stricter than the source's `parseInt`; recorded in the handoff.
- **D4 — schedule list controls.** Recommended: each session row becomes a `GridLayout` with columns `*,auto`: column 0 is the existing row content with `@tap` navigating per D1 (accessibility role button/link, label = session name); column 1 is a sibling `Button` (never nested in the tappable content) with text `Favorite` in all mode and `Remove` in favorites mode, `automationText` `favorite-<id>` / `remove-<id>`. Keep `automationText` `session-<id>` on the row content and the existing text. Dialogs through `@nativescript/core` `Dialogs`, same semantics and wording as RN04: not-favorite → commit `favoriteAdded` first, then `alert({ title: 'Favorite Added', okButtonText: 'OK' })`; already favorite (reproduced source quirk) → `confirm({ title: 'Favorite already added', message: 'Would you like to remove this session from your favorites?', cancelButtonText: 'Cancel', okButtonText: 'Remove' })`; favorites-mode Remove → same confirm titled `Remove Favorite`. Cancel commits nothing; Remove commits `favoriteRemoved`. The decision logic is a pure `listFavoriteAction(mode, isFavorite)` in `session-detail.ts` returning the add-then-alert or confirm-remove plan with its exact strings. Android dialogs cannot mark a destructive button; disclosed. Alternative: ListView `itemTap` for navigation — Android may suppress `itemTap` on rows that contain a `Button`; not recommended.
- **D5 — detail UI.** Recommended: NEW `src/components/SessionDetail.vue`: `Page` with ActionBar title `Session`, a `ScrollView`. Idle/loading: `Loading session…` with an `ActivityIndicator` (dispatch `load` on mount only when `idle`). Error: `Unable to load sessions.`, the message and `Retry` (dispatch `retry`). Never show "not found" before ready. Ready, known: heading with the session name; track names; description (omitted when empty); original `timeStart–timeEnd`; location. Ready, unknown: `Session not found.`, no session content, toggle visible but disabled and committing nothing. Favorite toggle: in-page `Button`, text `Add to favorites` / `Remove from favorites`, `automationText` `favorite-toggle`, accessibility state selected = favorite; commits immediately, no dialog. Placeholders: a `Share` button and `Watch`, `Add to Calendar`, `Mark as Unwatched`, `Download Video`, `Leave Feedback`, all disabled with no handlers. Fixed light palette as NS03.
- **D6 — development-only direct-entry harness.** Recommended: NativeScript has no URL deep link router; the harness stands in for RN04's cold deep link. Pure `directEntrySessionId(extra: string | null | undefined, isDev: boolean): string | undefined` in `session-detail.ts` (returns the raw extra only when `isDev` and the extra is a non-empty string). In `Home.vue`, on the root `Frame`'s first `loaded`, read the Android launch intent string extra `ns04SessionId` (`Application.android.startActivity?.getIntent()?.getStringExtra('ns04SessionId')`) only under `__DEV__`; when present, `$navigateTo(SessionDetail, { frame, props: { sessionId }, animated: false })` once, on top of the schedule, so back lands on the schedule (RN04 `initialRouteName`). Raw strings pass through unchanged so `abc` / `3abc` reach D3. Launch: `adb shell am start -n dev.translationtest.ns/com.tns.NativeScriptActivity --es ns04SessionId <value>` after `force-stop`. Release builds are not built in this package; the `__DEV__` gate is proven by source and the debug build mode only (disclosed). Alternative: a separate dev entry point or build flag — more configuration surface, not recommended.
- **D7 — tests.** Recommended: Vitest only, real core and real loader: (1) `favoriteAdded`/`favoriteRemoved` semantics, composition of two consecutive adds, no-ops before load, deep-frozen prior state untouched; (2) `sessionById`/`isFavorite` for known, unknown and pre-load; (3) after favoriting through the new mutations, favorites mode via `scheduleGroups` matches the frozen `favorites-some` and `favorites-order` cases (test-only reference import as NS03); (4) `parseSessionId` table (`3` → 3; `003` → 3, since RN04's rule accepts any ASCII-digit string by numeric value; `9999` → 9999, unknown at lookup; `abc`, `3abc`, `-1`, empty and ` 3` → undefined); (5) `listFavoriteAction` for all three branches with exact strings; (6) `directEntrySessionId` with dev/non-dev and empty/missing extras. Navigation, dialogs, rendering and back are proven on the device only (disclosed, as NS03). Keep all 34 NS03 tests.
- **D8 — device observation.** Recommended: rebuild the debug APK, `adb install -r`, verify the installed hash, then capture PNG + compressed UI XML (taps only at bounds from the current XML; no text input; no hardware Back/Home keys — ActionBar back only; hardware back is NS07):
  1. Cold launch schedule; one swipe; record the first visible heading/row.
  2. Tap a known session row's content → detail (name, time, location, `Add to favorites`).
  3. Tap the toggle → `Remove from favorites`, no dialog; ActionBar back → schedule at the same scroll position, same mode, no loading UI.
  4. `Favorite sessions` → that session listed; `Remove` → `Remove Favorite` dialog; Cancel → row stays; `Remove` again → Remove → `No favorite sessions.`
  5. `All sessions`; `Favorite` on a non-favorite → `Favorite Added` dialog; OK; `Favorite` on it again → `Favorite already added` dialog; Cancel (still favorite, verified in favorites mode); then Remove.
  6. Cold direct entry (D6) with `3` → detail for session 3; ActionBar back → schedule. With `9999` and `abc` → `Session not found.`, toggle disabled.
  7. Bounded PID logcat per launch.
  Alternative: hardware Back keys in this package — not recommended (NS07 owns hardware back).
