## Outcome and boundaries

Add the track filter to the NativeScript target. This is the NativeScript counterpart of RN05, with the same business cases: a schedule control opens a native modal holding a local draft of track selections; Done applies the draft as a whole replacement of `selectedTracks`; any close without Done discards the draft (plan: "native cancellation discards draft"). Reset and Deselect All clear the draft, Select All checks every row; none of them closes the modal or touches applied state. Filters never reset search, mode or favorites and never reload the fixture. Swipes (NS06), iOS presentation, track icons, large text, dark mode and full acceptance (NS07) are out of scope. No dependency changes.

## Decisions to answer (human)

- **D1 — store addition.** Recommended: in `conference-store.ts` add a getter `trackOptions: { name: string; checked: boolean }[]` — `[]` unless ready with a conference and selection, otherwise public core `sortTracksByName(conference.tracks)` mapped to `{ name, checked: selection.selectedTracks.includes(name) }`; a fresh array each read, never stored. Extend the `ConferenceStore` getters type. Done uses the existing `setSelectedTracks`; no new mutation. Keep every NS03/NS04 export and behavior.
- **D2 — draft logic.** Recommended: NEW pure `src/state/track-filter.ts` (no NativeScript imports): `toggleTrack(draft, name)`, `setAllTracks(draft, checked)`, `checkedTrackNames(draft)` (displayed/sorted order), all returning fresh arrays; and `applyFilterResult(store, result)` — commits `setSelectedTracks(result)` when `result` is an array (an empty array applies zero tracks: source parity), and does nothing for `undefined`/`false` (any close without Done). The modal's `closeCallback` calls only `applyFilterResult`.
- **D3 — modal presentation.** Recommended: NEW `src/components/TrackFilter.vue` opened with `$showModal(TrackFilter, { fullscreen: true, closeCallback })` from the schedule. Its root is a `Frame` hosting a `Page` with ActionBar title `Filter Sessions` and a `NavigationButton` (Android close icon, `automationText` `Close filter`) that calls `$closeModal()` with no data. The draft is local component state initialized once from `trackOptions` when the modal opens (the store is already ready: the Filter control is disabled until ready); reopening creates a fresh draft from the applied selection. Alternative: a non-fullscreen dialog-style modal — less room for 10 rows plus four controls, not recommended.
- **D4 — filter rows and controls.** Recommended: heading `Tracks`; one row per track in sorted order (`Communication, Design, Documentation, Food, Ionic, Navigation, Services, Tooling, Vue, Workshop` for this fixture), each a `GridLayout` `*,auto` with a `Label` (the name) and a native `Switch` bound to the draft (`automationText` `track-<name>`); the UI XML exposes `checked`. Tapping the switch toggles only that draft row. No icons (source shows them on iOS only). Buttons inside the page, Android parity (`SessionListFilter.vue:5-8,13,37-40`): `Reset` (clears the draft), `Deselect All` (clears), `Select All` (checks all), `Done` (`$closeModal(checkedTrackNames(draft))`). Reset is not Cancel. Alternative: tappable rows with a check-mark label and `accessibilityRole` checkbox — custom state rendering instead of a native control.
- **D5 — schedule control.** Recommended: in `Schedule.vue`, put the `SegmentedBar` and a new `Button` (`text` `Filter`, `automationText`/accessibility label `Filter sessions`, disabled until ready like the other controls) in one row (`GridLayout` `*,auto`). Tapping it opens D3 with `closeCallback: result => applyFilterResult(store, result)`. Keep the NS03 SearchBar focus mechanism, states, empty messages and the NS04 row/button layout unchanged. Applying filters keeps search, mode and favorites and does not reload. Alternative: an ActionBar `ActionItem` — Android places it in an overflow menu or icon slot, and its disabled state is less reliable.
- **D6 — tests.** Recommended: Vitest only, real core and real loader. Store: `trackOptions` empty before load; after load all 10 sorted and checked; after `setSelectedTracks(['Ionic'])` only Ionic; after `[]` none; fresh array per read. Draft helpers: toggle, select/deselect all, Reset, sorted `checkedTrackNames`, immutability of inputs. `applyFilterResult` through a real store: Done with only Ionic → `scheduleGroups` equals `single-track`; Ionic + Design then search `Ionic` → `search-plus-track`; empty array → `no-tracks` (and `[]` groups), then all → `default-all`; `undefined` and `false` → applied selection and groups unchanged; favorites 12 and 3 via `favoriteAdded`, favorites mode, Food only → `favorites-some` with mode and search unchanged; loader call count unchanged throughout. Modal rendering, Switch taps and native dismissal are proven on the device only (disclosed, as NS03/NS04). Keep all 69 NS04 tests.
- **D7 — device observation.** Recommended: rebuild, `adb install -r`, verify the installed hash, cold launch, then PNG + UI XML at each step (taps only at bounds from the current XML; no text input):
  1. Schedule with the enabled `Filter` button.
  2. Open the filter: `Filter Sessions`, `Tracks`, 10 rows in sorted order, all switches checked, the four buttons.
  3. Tap Ionic's switch off (only Ionic unchecked); `Deselect All` (all unchecked); `Select All` (all checked); `Reset` (all unchecked) — the draft only.
  4. Check only Ionic; `Done` → schedule shows the `single-track` rows (sessions 4, 2, 5; no session 3), mode and search unchanged.
  5. Reopen: only Ionic checked (mirrors the applied filter). Change the draft (check Design); tap the ActionBar close button → schedule unchanged (still `single-track`); reopen → only Ionic checked again.
  6. Change the draft again; **one** Android Back key event, sent only after the current XML shows the filter modal → modal closes, schedule unchanged. This is the plan's "native cancellation" and the only hardware key this package allows.
  7. Reopen; `Deselect All`; `Done` → `No sessions match your search or filters.`, no rows. Reopen: all unchecked. `Select All`; `Done` → the `default-all` rows return.
  8. Bounded PID logcat; `pidof` before and after (same process throughout).
  Alternative: no hardware Back at all (close button only) and record native-Back cancellation as NS07 — leaves the plan's NS05 acceptance line device-unverified.
