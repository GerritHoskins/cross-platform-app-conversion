## Coordinator decisions for this package

- **Additive types.** `Speaker` stays `{ id, name }` and `Conference` is unchanged. A React Native test builds `{ id: 1, name: 'Ada' }` as a `Speaker` (`migration/react-native/__tests__/schedule-screen.test.tsx:57`), so widening `Speaker` would break a target. Profiles are a new type `SpeakerProfile extends Speaker`, produced by a new function over the same raw data.
- **One validation path.** `normalizeSpeakerProfiles` reuses `normalize.ts`'s existing helpers and error paths for `id` and `name` (C02 rules: a missing or empty name throws `ConferenceDataError`). P02's synthetic `/supplemental/missingFields` case expects `name: ''` for a speaker without a name; core keeps the stricter C02 rule for names (the fixture has no nameless speaker), and checks the P02 defaults only for `title`, `about` and `profilePic`. Record this in the handoff as a deliberate core decision, not a failure.
- **Optional text fields.** `title`, `about`, `profilePic`: absent, `null` or `''` become `''`; a string is kept as is; any other type throws `ConferenceDataError` at its path (for example `speakers[3].title`). This follows P02 CD3, with the existing core strictness for wrong types.
- **Route IDs are `unknown`.** Router params can be `string`, `string[]` or `undefined`; anything that is not a string matching P02 CD3 is malformed.

## Fixed interface

```ts
// types.ts additions
export interface SpeakerProfile extends Speaker {
  title: string;
  about: string;
  profilePic: string;
}
export type SpeakerNotFoundReason = 'malformed-id' | 'unknown-id';
export type SpeakerLookup<T extends Speaker = Speaker> =
  | { status: 'found'; speaker: T }
  | { status: 'not-found'; reason: SpeakerNotFoundReason };

// normalize.ts addition
export function normalizeSpeakerProfiles(raw: unknown): SpeakerProfile[];

// speakers.ts
export function sortSpeakers<T extends Speaker>(speakers: readonly T[]): T[];
export function sessionsForSpeaker(sessions: readonly Session[], speakerId: number): Session[];
export function parseSpeakerRouteId(value: unknown): number | null;
export function findSpeakerByRouteId<T extends Speaker>(speakers: readonly T[], routeId: unknown): SpeakerLookup<T>;
```

No other new exports. `index.ts` re-exports the new types and functions and sets `CORE_API_VERSION = 2`.

## Behavior (cite the contract section in code comments)

- `normalizeSpeakerProfiles(raw)`: reads `raw.speakers` with exactly the same `id`/`name` validation, error paths and messages as `normalizeConference` (share the helpers; do not copy them). Returns new `{ id, name, title, about, profilePic }` objects in input order, with the optional-field rule above. It does not validate sessions or tracks. For the fixture it returns 13 profiles whose fields equal `/speakerDetails` (ignoring `profilePicFile`, `profilePicSha256`, `profilePicBytes`, which are asset metadata for the targets).
- `sortSpeakers`: new array; compare `name` by UTF-16 code units (`<` / `>`), case-sensitive, no locale, no case folding, no Unicode normalization; equal names by numeric `id` ascending; equal name and id keep input order (stable sort). P02 CD1.
- `sessionsForSpeaker`: new array of the sessions whose `speakerIds` include `speakerId`, in input (store) order; no time sort; an ID with no sessions gives `[]`. P02 CD2.
- `parseSpeakerRouteId`: a `string` matching `^[1-9][0-9]*$` whose `Number` value is a safe integer gives that number; everything else (`undefined`, `null`, arrays, numbers, `''`, whitespace, signs, zero, leading zeros, decimals, trailing characters, unsafe integers) gives `null`. No trimming, no partial parsing. P02 CD3.
- `findSpeakerByRouteId`: `null` from `parseSpeakerRouteId` gives `{ status: 'not-found', reason: 'malformed-id' }`; a valid ID with no speaker gives `reason: 'unknown-id'`; otherwise `{ status: 'found', speaker }` with the same object from the input array (no copy).
- Every function is pure: no input mutation, no module-level state.
